# Forecasts

Published Oct/Nov 2026 UPI forecasts, generated by `src/make_forecast.py`
(run: `python src/make_forecast.py`). The script trains on everything through
**2026-09** and writes `forecast_2026-10-15.csv`.

## File: `forecast_2026-10-15.csv`

One row per `(month, target, model)`. Columns:

| Column | Meaning |
|---|---|
| `month` | forecast month (`2026-10`, `2026-11`) |
| `target` | `avg_daily_volume`, `monthly_volume_mn`, `avg_daily_value`, `monthly_value_cr` |
| `model` | `ETS_damped`, `b2`, `naive+growth`, `SARIMA` |
| `point` | point forecast (daily rate for `avg_daily_*`; month total for `monthly_*`) |
| `lower`, `upper` | empirical backtest error range (see below) |
| `trained_through` | `2026-09` |
| `interval_method` | how the interval was built, incl. `n` and years |
| `median_signed_error_pct` | median signed log error over the festival backtest, as a percent (bias) |
| `point_in_range` | `True` if the point falls inside its own error range (i.e. the range straddles zero) |
| `designated_primary` | `True` for the shipped primary model of that target |

All four models are shipped for both series (volume and value).

## Primary models (selection rule adopted after the first version failed a sanity check)

The first version used overall backtest MAPE and picked b2 for value; its October forecast fell 4% below September, contradicting last year's festival lift, so the rule was changed to festival-season MAPE. The rule was fixed before the October 2026 actuals were published.

For each target we pick the model with the **lowest festival-season MAPE**
(origins 2019-2025, Oct+Nov pooled), tie-broken by the **median signed log
error closest to zero**, then by the **simpler** model. We deliberately do NOT
choose by overall (all-months) MAPE.

| Series | Primary | Festival MAPE | Median signed log err | Why |
|---|---|---|---|---|
| volume | **`ETS_damped`** | 3.52% | +0.0202 | lowest festival MAPE **and** closest-to-zero median |
| value | **`naive+growth`** | 5.95% | -0.0385 | lowest festival MAPE **and** closest-to-zero median |

Runner-up context: on value, `b2` was the *worst* festival model (MAPE 20.87%,
median signed log error +0.20), and plain `ETS_damped` was biased too (+0.09), so
neither is used for value. On volume `ETS_damped` beats `naive+growth`,
`SARIMA` and `b2` on festival MAPE.

## Intervals

Intervals are **not** a 95% CI. Each is the **empirical range** of that model's
own festival-season backtest errors.

- Backtest origins: one per year **2019-2025** (7 origins, so **n = 7**).
- At each origin the model is trained **only** on data up to that September and
  then forecasts October (step 1) and November (step 2).
- Errors are signed log errors, `e = log(actual) - log(point)`.
- For a 2026-10 row: `lower = point * exp(min e)`, `upper = point * exp(max e)`
  over the 7 **October** errors. For 2026-11: the 7 **November** errors.

**WARNING — read the interval against the point.** Because the range keeps the
sign, a range that lies **entirely above or entirely below the point** is a
warning that the model is **systematically biased in festival months**; it is
**not** evidence that the forecast is fine. `point_in_range = False` marks these
rows. For example `b2` on value has an interval fully above the point, matching
its large positive median signed error.

The same n=7 backtest both selects the model and sets the range, so the range is somewhat optimistic.

**Caveat on the error range.** The 2019-2021 origins are trained on shorter
histories and sit inside UPI's fast-growth period, so their festival errors are
larger than today's — this widens the published range. Treat it as a
conservative, honest band rather than a tight forecast uncertainty. The
2022-2025 check window (printed by the script) confirms the same model ranking
with smaller errors.
